# 状态引擎（State Engine）

**一个「类似世界书」的扩展，但它不靠关键词吃饭。**

写卡玩卡的人都懂那种感觉：世界书写得贼厚，真正能触发它的关键词就那么几个，大部分内容躺在书里吃灰。或者你只想用某条里的一小段，却不得不把整段一起塞给 AI，又占 token 又分散注意力，调着调着人就麻了。

状态引擎换个玩法：把内容拆成一条一条的小卡片，按类型装进【合集】。每次只从合集里抽一张，单独塞给这一轮 AI。抽哪张、什么时候抽，你说了算。

插件本身是空的，跟世界书刚装好一样，内容你自己填。

## 它有什么功能

- **四种抽法**：手动点、每 N 楼自动、聊天里出现关键词自动、让 AI 自己判断要不要抽。
- **抽过的不重复**：同一个合集里，最近抽过的几条会先进冷却，过几轮再放出来。
- **能设保质期**：只留这一轮、留 N 轮、一直留着，或者让 AI 自己说「这个不用了」。
- **能连锁**：A 抽到的内容里提到了 B 的关键词，B 也能跟着抽一张。谁叫醒谁都能单独关掉。
- **能绑定角色**：比如这份衣柜只给「沈微澜」用，别人不触发。
- **能导入导出**：写好一份合集可以导出成文件，发给别人或者留备份。

## 能拿来干嘛

只要是「一堆选项里挑一个」的东西，都能装进来。

| 你想要的 | 合集里放什么 |
| --- | --- |
| 角色别老穿同一套 | 几套衣服，每套一段描写 |
| 别老用同一套反应 | 被夸、被拒、被追问时的几种反应 |
| 约会别老去同一家店 | 几个地点，每个写清楚长什么样、能干嘛 |
| 新 NPC 别空着手来 | 技能、特长，登场时抽一两个 |
| 道具别只是背景板 | 几样东西，抽一件，这轮用不用再掷一次 |

## 和世界书到底差在哪

| | 世界书 | 状态引擎 |
| --- | --- | --- |
| 怎么触发 | 关键词命中 | 手动 / 楼层 / 关键词 / AI 判断 |
| 一次给多少 | 命中条目的全文 | 抽 1～N 条，只给要的 |
| 会不会重复 | 关键词在就一直在 | 有冷却，抽过的不连着来 |
| 内容会不会变 | 固定文本 | 每次抽的可能不一样 |
| 能不能组合 | 各管各的 | 能，抽到的内容可以叫醒别的合集 |

## 安装

把整个 `state-engine` 文件夹放到：

```
SillyTavern/public/scripts/extensions/third-party/state-engine/
```

刷新酒馆页面，顶栏会出现一个骰子图标（在世界书图标旁边）。

## 面板

点顶栏的骰子打开。面板宽度跟聊天栏一致，不会挡住左边的预设和右边的角色卡。从上到下是四块：

- **本轮上场**：这一轮真正交给 AI 的内容，一条一行。每行写着它从哪个合集来（嵌套时是 `大合集 › 子合集 › 条目`），右边是它在剧里还能待多久：`剩 3 楼`、`由 AI 结束`、或 `— 常驻 —`。超过 3 条时折叠成「另有 N 条」。
- **合集 / 条目**：左边是合集列表，子合集用 `└` 缩进；右边是选中合集的条目表。点任意一行，就在它下面展开改名和内容，不跳页。
- **底部抽条**：常驻的「抽一条」按钮。左边写着待抽的合集的条目数与权重合计，右边按钮，面板打开时按**空格**也能抽。
- **底部折叠区**：`后台记录`（每次抽签的楼层、合集、抽到了什么、因为什么触发）、`设置`（AI 判定模板与深度、本轮注入预览）。

右上角：`启用`（总开关）、`新建合集`、`导入`、`导出全部`。选中合集后，条目表下方的「合集设置」里才有 `重抽`、`清空记录`、`导出此合集`、`删除合集`。

## 合集里有什么

| 字段 | 说明 |
| --- | --- |
| 合集名称 | 显示用，也是注入时的标题 |
| 绑定 | `不绑定` / `MVU 角色` / `当前角色` / `手动输入` |
| 每次抽取 | 一次抽几条 |
| 冷却轮数 | 抽过的条目最近几轮不再出现 |
| 持续时长 | 抽中的内容保留几轮、永久保留，还是由 AI 判断何时结束 |
| 触发 | 手动、楼层自动、关键词、AI 判定，可多选 |
| 递归 | （旧版兼容字段，现在用下面的「被谁唤起」） |
| 被谁唤起 | 勾选哪些合集抽中时，顺手把这个合集也抽一次；「只在被唤起时出场」会让它平时不被楼层/关键词/AI 触发 |
| 上级合集 | 把这个合集挂到另一个合集下面，变成它的「子合集」。上层抽签时会先抽子合集，再让子合集抽自己的条目，最多三层 |
| 只能被上级抽中 | 勾上后，平时的关键词、楼层自动、AI 判定都不会碰它，只有它挂在的那个上层合集抽签时才会轮到它 |
| 扫描最近 N 条 / 来源 | 关键词在最近几条消息里找；只看玩家、只看 AI、或两者 |
| 还从哪找 | 除了聊天，还可以勾角色描述、角色性格、情景、用户设定、角色备注、世界书 |
| 注入位置 / 深度 / 角色 | 聊天记录里、系统提示末尾、提示词最前；深度只对「聊天记录」生效 |
| 条目 | 名称、内容、概率（相对权重） |

条目没有数量上限。概率是相对值：`1` 和 `3` 放在一起，后者出现的次数大约是前者的三倍；填 `0` 表示这条永远不出现（可以先留着）。

## 抽中的内容持续多久

每个合集可以单独设置，抽中之后这份内容留多久：

| 方式 | 行为 |
| --- | --- |
| 按轮数 | 填 `1` 就只在抽中那一轮生效；填 `3` 就是抽中当轮算第 1 轮，再留两轮 |
| 永久 | 一直留着，直到你点「重抽」或「清空记录」 |
| 由 AI 判断结束 | 一直留着，直到模型在回复最后单独一行写 `<!--SE-END:合集id-->` |

到期时插件会自动清空这一份的当前值，注入也跟着消失，后台记录里会留下 `expire`（按轮数到期）或 `ai-end`（模型喊停）。

冷却记录不受影响：到期只是清掉「当前是什么」，不会把「刚抽过什么」也忘掉，所以不会立刻又抽回同一条。

## 四种触发

1. **手动**：点面板底部的「抽一条」（面板打开时按空格也行）。
2. **楼层自动**：每 N 层抽一次，从上次抽取的楼层往后数。
3. **关键词**：最近几条消息（以及你勾选的角色描述、性格、情景、用户设定、备注、世界书）里出现了合集的任意一个关键词就抽。支持 `/正则/` 写法。
4. **AI 判定**：把一份说明发给模型，模型在回复最后单独一行写 `<!--SE:合集id-->`，下一轮生成时插件看到标记就抽。说明可以在「设置」里改，也可以给单个合集写补充说明；「设置」里还能调这份说明的插入深度（数字越小越靠近最新一条消息，模型越容易照做）。
   说明里会把这个合集前 24 个条目的名字列出来，模型知道有哪些选项可申请；没列到的条目也能被抽到，只是模型看不到名字。

每个合集都有「被谁唤起」：在别的合集的名字前面打勾，那些合集抽中时，就会顺手把这个合集也抽一次，最多三层，不会循环。

- 不勾任何一项 = 没人能唤起我，我只按自己的触发方式出场。
- 勾了某一项 = 那个合集抽中时（手动抽也算），我也会跟着抽一次，后台记录写 `summoned`。
- **只在被唤起时出场**：勾上以后，楼层自动、关键词、AI 判定都不碰它，只有被人唤起时才抽；手动点「抽一条」仍然可以。
- 这跟「上级合集」是两件事：上级合集管的是树形结构（侧栏缩进、先抽哪一类），「被谁唤起」管的是「谁抽中了我，我就跟着出现」。

同一楼层只会决定一次：重 roll、swipe、重新生成都沿用这一楼的结果；想换请点「重抽」。

## 合集可以套合集

合集不是只能平铺，可以像文件夹一样套起来：

- 在合集的「上级合集」里选另一个合集，它就变成对方的**子合集**；侧栏里会缩进显示，前面带 `└`。
- 上层合集抽签时，如果它有子合集，会先按权重抽一个子合集，再让这个子合集抽自己的条目。抽签结果会同时记在上下两层的「当前值」里，后台记录会写 `nested`。
- 最多套三层，挂成环会被拦住（把合集挂到自己的下级里会提示，不会写进去）。
- **只能被上级抽中**：勾上以后，关键词、楼层自动、AI 判定都不会碰它，只有它挂靠的那个上层合集抽签时才会轮到它。适合「身体特征 → 宫口特质 → 具体特质」这种一层层往下选的场景。
- 子合集的权重（`entryWeight`）控制它在兄弟合集里被抽中的相对机会；填 `0` 等于这次不参与。

套起来之后，上层一般不用放条目——它可以是个空容器，只负责「先选哪一类」，内容都在子合集里。

## 绑定角色与 MVU

如果角色卡的世界书里有 `[InitVar]` 条目（MVU 变量），插件会读出里面的顶层名字，列在下拉框里（比如「沈微澜」）。

- 选一个名字后，这个合集只在这个名字出现在最近 10 条消息里时才抽、才注入。注入标题会变成 `【沈微澜·衣柜】`。
- 读不出来也没关系，选「手动输入」自己填名字。
- 不绑定就是所有角色通用。

## 数据存在哪

每份聊天自己的数据，存在 `chatMetadata.stateEngine` 里，跟着聊天走。换聊天、换角色不会串。

- `导出此合集` / `导出全部` 得到 JSON 文件，可以发给别人，也可以留作备份。
- `导入 JSON` 接受单文件或多文件；同一个 `id` 会覆盖更新。
- 删除合集只删这份聊天里的这一份，不影响别的聊天。

## JSON 格式（schema 4）

```json
{
  "schema": 4,
  "id": "outfit",
  "name": "衣柜",
  "binding": { "type": "none", "name": "" },
  "trigger": { "manual": true, "auto": false, "autoEvery": 3, "keyword": true, "ai": false },
  "keywords": ["换衣服", "外套"],
  "scan": { "depth": 4, "source": "both", "fields": [] },
  "recursion": { "canBeRecursed": true, "canRecurse": false, "delay": false },
  "summon": { "by": [], "only": false },
  "nesting": { "parent": "", "onlyFromParent": false, "entryWeight": 1 },
  "hold": { "mode": "forever", "turns": 3 },
  "inject": { "position": "chat", "depth": 4, "role": "system" },
  "cooldown": 2,
  "pick": 1,
  "aiPrompt": "",
  "items": [
    { "id": "shirt-white", "name": "白衬衫", "text": "洗得发白的棉质白衬衫。", "weight": 1 }
  ]
}
```

`nesting.parent` 填上层合集的 `id` 就是子合集；空字符串表示顶层。`onlyFromParent` 为 `true` 时只有上层抽签能叫醒它。纯容器合集可以写 `"items": []`。
`summon.by` 填一组合集 `id`：那些合集抽中时，会顺手把这个合集也抽一次。`summon.only` 为 `true` 时，这个合集平时不被楼层/关键词/AI 触发，只能在被唤起或手动「抽一条」时出场。

旧版（schema 1、2、3）的包在导入时会自动升级；以前填过的合集也会在读取时补齐新字段。

## 注入位置为什么只有三个

插件用的是酒馆给扩展的注入接口，它只提供三个位置：聊天记录里（可以设倒数第几条）、系统提示末尾、提示词最前。

世界书条目里的「角色定义前/后、示例消息前/后、作者注释前/后、锚点」是**世界书条目专属**的位置，扩展接口拿不到，所以这里不会出现。如果你需要那些位置，可以把这里抽到的内容导出，再手动放进世界书。

## 已知边界

- 内容是每份聊天自己的，不是全局的。
- MVU 名字识别靠 `[InitVar]` 条目的顶层键；名字藏得很深的卡识别不出来，用「手动输入」。
- 「被谁唤起」最多传三层，不会循环。
- 合集嵌套也最多三层，超过的部分不会继续往下抽。
- 注入位置受扩展接口限制，只有三种。
- 还没有批量文本导入（把一整段文字拆成条目）。
- 条目编辑是即时保存的，没有撤销按钮；改坏了可以「导出此合集」留一份再改。
