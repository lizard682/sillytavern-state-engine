# 状态引擎（State Engine）

> 让世界书学会「按需出场」，而不是每次都把整本书塞给 AI。

## 它解决什么问题

写卡和玩卡的人大概都遇到过这两种别扭：

- **世界书太臃肿**：设定写得很细，但真正能触发它的关键词就那么几个，大部分条目常年躺在书里吃灰。
- **整段发送太浪费**：只想用某个综合条目里的一小段，却不得不把整段内容一起塞进上下文，占 token、分散 AI 的注意力，调到最后热情都被磨没了。

状态引擎换了个思路：**不把内容写进世界书等关键词来捞，而是把内容拆成「合集」和「条目」，在合适的时机按规则抽一条，单独注入这一轮。**

插件本身不带任何内容——就像世界书刚装好时是空的。合集和条目都由你自己填。

## 它和世界书有什么不同

| | 世界书 | 状态引擎 |
| --- | --- | --- |
| 触发方式 | 关键词命中 | 手动 / 楼层自动 / 关键词 / AI 判定 |
| 一次给多少 | 命中条目的全文 | 从合集里抽 1～N 条，只给你要的 |
| 会不会重复 | 关键词在就一直在 | 有冷却，最近抽过的不再出现 |
| 内容会不会变 | 固定文本 | 每次抽签都可能不同 |
| 能不能组合 | 条目各自为战 | 递归：抽中的内容可以叫醒别的合集 |

## 它能拿来做什么

衣柜（角色换衣服）、动作反应（避免八股应对）、场景库（约会去不同的地方）、NPC 技能（新角色登场随机带技能）、道具库（手边有什么、这轮用不用）……

任何「有一堆选项、每次只需要其中一个」的东西，都可以做成合集。合集和条目数量都没有上限。

## 几个设计上的小心思

- **抽签可复现**：种子存在聊天里，同一段对话重开也能抽到同样的结果。
- **同一楼层只决定一次**：重 roll、swipe、重新生成都沿用这一楼的结果，不会闪来闪去。
- **抽中的内容有保质期**：可以按轮数过期、永久保留，或者让 AI 自己判断什么时候结束。
- **递归可控**：谁能叫醒谁、能不能继续扩散，都由每个合集自己决定，默认只扩散一层。
- **内容跟聊天走**：每份聊天有自己的合集和抽签记录，不会串台。

## 安装

把整个 `state-engine` 文件夹放到：

```
SillyTavern/public/scripts/extensions/third-party/state-engine/
```

刷新酒馆页面，顶栏会出现一个骰子图标（在世界书图标旁边）。

## 面板

点顶栏的骰子打开。面板宽度跟聊天栏一致，不会挡住左边的预设和右边的角色卡。

- 左边是合集列表，点一个切换。
- 右边是选中合集的编辑区：最上面是可折叠的「合集设置」（名称、绑定、抽取、触发、递归、注入位置），下面是条目表。设置折叠时，条目就是画面的主体。
- 右上角：`启用插件`（总开关）、`新建合集`、`导入`、`导出全部`。
- 顶部按钮：`抽一次`（马上抽一次）、`重抽`（在同一个楼层换一个）、`清空记录`、`导出此合集`、`删除合集`。
- 条目区下面有「本轮注入预览」：展开就能看到这一轮真正发给 AI 的原文。
- 底部「后台记录」：每次抽签的楼层、合集、抽到了什么、因为什么触发。
- 底部「设置」：AI 判定的提示词模板与插入深度，可以直接改。

## 合集里有什么

| 字段 | 说明 |
| --- | --- |
| 合集名称 | 显示用，也是注入时的标题 |
| 绑定 | `不绑定` / `MVU 角色` / `当前角色` / `手动输入` |
| 每次抽取 | 一次抽几条 |
| 冷却轮数 | 抽过的条目最近几轮不再出现 |
| 持续时长 | 抽中的内容保留几轮、永久保留，还是由 AI 判断何时结束 |
| 触发 | 手动、楼层自动、关键词、AI 判定，可多选 |
| 递归 | 谁能叫醒它（可被其他合集递归激活）、它能不能继续叫醒别人、是否只在递归阶段激活 |
| 扫描最近 N 条 / 来源 | 关键词在最近几条消息里找；只看玩家、只看 AI、或两者 |
| 还从哪找 | 除了聊天，还可以勾角色描述、角色性格、情景、用户设定、角色备注、世界书 |
| 注入位置 / 深度 / 角色 | 聊天记录里、系统提示末尾、提示词最前；深度只对「聊天记录」生效 |
| 条目 | 名称、内容、概率（相对权重） |

条目没有数量上限。概率是相对值：`1` 和 `3` 放在一起，后者出现的次数大约是前者的三倍；填 `0` 表示这条永远不出现（可以先留着）。

## 抽中的内容持续多久

每个合集可以单独设置，抽中之后这份内容留多久：

| 方式 | 行为 |
| --- | --- |
| 按轮数 | 填 `1` 就只在抽中那一轮生效；填 `3` 就是抽中当轮算第 1 轮，再留两轮 |
| 永久 | 一直留着，直到你点「重抽」或「清空记录」 |
| 由 AI 判断结束 | 一直留着，直到模型在回复最后单独一行写 `<!--SE-END:合集id-->` |

到期时插件会自动清空这一份的当前值，注入也跟着消失，后台记录里会留下 `expire`（按轮数到期）或 `ai-end`（模型喊停）。

冷却记录不受影响：到期只是清掉「当前是什么」，不会把「刚抽过什么」也忘掉，所以不会立刻又抽回同一条。

## 四种触发

1. **手动**：点面板上的「抽」。
2. **楼层自动**：每 N 层抽一次，从上次抽取的楼层往后数。
3. **关键词**：最近几条消息（以及你勾选的角色描述、性格、情景、用户设定、备注、世界书）里出现了合集的任意一个关键词就抽。支持 `/正则/` 写法。
4. **AI 判定**：把一份说明发给模型，模型在回复最后单独一行写 `<!--SE:合集id-->`，下一轮生成时插件看到标记就抽。说明可以在「设置」里改，也可以给单个合集写补充说明；「设置」里还能调这份说明的插入深度（数字越小越靠近最新一条消息，模型越容易照做）。
   说明里会把这个合集前 24 个条目的名字列出来，模型知道有哪些选项可申请；没列到的条目也能被抽到，只是模型看不到名字。

递归由每个合集自己控制，最多三层：

- **可以被其它合集递归激活**：别的合集抽中的内容里命中它的关键词时，它也会抽；
- **抽中后继续叫醒别的合集**：它自己抽完后，还能再去叫醒别人；
- **只在递归阶段激活**：普通触发时跳过它，只有被递归时才抽。

默认只有「可以被递归激活」是开的，所以不会连锁失控；想让它继续扩散，就把「继续叫醒别人」也打开。

同一楼层只会决定一次：重 roll、swipe、重新生成都沿用这一楼的结果；想换请点「重抽」。

## 绑定角色与 MVU

如果角色卡的世界书里有 `[InitVar]` 条目（MVU 变量），插件会读出里面的顶层名字，列在下拉框里（比如「沈微澜」）。

- 选一个名字后，这个合集只在这个名字出现在最近 10 条消息里时才抽、才注入。注入标题会变成 `【沈微澜·衣柜】`。
- 读不出来也没关系，选「手动输入」自己填名字。
- 不绑定就是所有角色通用。

## 数据存在哪

每份聊天自己的数据，存在 `chatMetadata.stateEngine` 里，跟着聊天走。换聊天、换角色不会串。

- `导出此合集` / `导出全部` 得到 JSON 文件，可以发给别人，也可以留作备份。
- `导入 JSON` 接受单文件或多文件；同一个 `id` 会覆盖更新。
- 删除合集只删这份聊天里的这一份，不影响别的聊天。

## JSON 格式（schema 3）

```json
{
  "schema": 3,
  "id": "outfit",
  "name": "衣柜",
  "binding": { "type": "none", "name": "" },
  "trigger": { "manual": true, "auto": false, "autoEvery": 3, "keyword": true, "ai": false },
  "keywords": ["换衣服", "外套"],
  "scan": { "depth": 4, "source": "both", "fields": [] },
  "recursion": { "canBeRecursed": true, "canRecurse": false, "delay": false },
  "hold": { "mode": "forever", "turns": 3 },
  "inject": { "position": "chat", "depth": 4, "role": "system" },
  "cooldown": 2,
  "pick": 1,
  "aiPrompt": "",
  "items": [
    { "id": "shirt-white", "name": "白衬衫", "text": "洗得发白的棉质白衬衫。", "weight": 1 }
  ]
}
```

旧版（schema 1、2）的包在导入时会自动升级；以前填过的合集也会在读取时补齐新字段。

## 注入位置为什么只有三个

插件用的是酒馆给扩展的注入接口，它只提供三个位置：聊天记录里（可以设倒数第几条）、系统提示末尾、提示词最前。

世界书条目里的「角色定义前/后、示例消息前/后、作者注释前/后、锚点」是**世界书条目专属**的位置，扩展接口拿不到，所以这里不会出现。如果你需要那些位置，可以把这里抽到的内容导出，再手动放进世界书。

## 已知边界

- 内容是每份聊天自己的，不是全局的。
- MVU 名字识别靠 `[InitVar]` 条目的顶层键；名字藏得很深的卡识别不出来，用「手动输入」。
- 递归最多三层，由每个合集的三个开关控制。
- 注入位置受扩展接口限制，只有三种。
- 还没有批量文本导入（把一整段文字拆成条目）。
- 条目编辑是即时保存的，没有撤销按钮；改坏了可以「导出此合集」留一份再改。
